Prediction Market Reboot Architecture

Three-layer design for durable state, concrete execution attempts, and orchestration policy. The UI and MCP tools call one shared User actor, and inspection reads the persisted actors directly.

State

  • Actor state stores account credits, market status, bet status, payment intent status, and audit IDs.
  • Growing collections use `OrderedMap` IDs stored on owner state.
  • All user-visible facts are inspectable through Reboot state.

Execution

  • Transactions handle atomic debits, bet creation, and audit writes.
  • Workflows handle simulated gateway calls and restart recovery.
  • Attempt history records started, succeeded, failed, timed out, and crashed states.

Orchestration

  • Creator-only resolution starts payout orchestration after close.
  • Gateway retries stop after three attempts, then mark review needed.
  • Audit logs are written before the UI depends on them.
